# Проверенная анатомическая модель зуба

Финальный ассет должен находиться по адресу `public/models/tooth.glb`. Сейчас проверенного GLB в репозитории нет. Сам факт успешной загрузки файла не подтверждает его медицинскую точность. Демонстрационные фигуры viewer-а предназначены только для разработки и тестов и всегда должны сопровождаться сообщением **«ДЕМО-PLACEHOLDER — НЕ КЛИНИЧЕСКАЯ МОДЕЛЬ»**.

## `tooth.demo.glb` — заглушка для разработки

`tooth.demo.glb` собирается скриптом из параметрических профилей и выполняет весь
контракт ниже: шесть узлов, метрический масштаб, +Y, 55 872 треугольника,
6 draw calls, без текстур. Он нужен, чтобы прогонять слои, выбор, разнесение и
поперечный разрез на настоящем GLB.

**Это не клиническая модель.** Форма правдоподобна, но не снята со скана и не
проверена стоматологом. Толщины слоёв анатомически упорядочены, но не точны:
цемент корня нарисован толще реальных 20–200 мкм, иначе слой не видно при
переключении.

Не переименовывайте его в `tooth.glb`. `loadModel` считает любой файл по адресу
`/models/tooth.glb` режимом `provided-model` и **не показывает плашку**
«ДЕМО-PLACEHOLDER» — она есть только у встроенных фигур (`?model=mock`). Под
именем `tooth.glb` заглушка молча выдаст себя за проверенный ассет. Для ручной
проверки во viewer-е копию можно положить временно и затем удалить.

Пересборка и проверка (путь к Blender зависит от машины):

```bash
blender --background --factory-startup --python-exit-code 1 --python scripts/blender/build-tooth-demo.py -- public/models/tooth.demo.glb
```

```bash
blender --background --factory-startup --python-exit-code 1 --python scripts/blender/validate-tooth-glb.py -- public/models/tooth.demo.glb
```

Валидатор читает сам GLB и проверяет формат, состав узлов, бюджеты и что длинная
ось действительно `+Y` (Blender работает в `+Z`, ось переворачивает экспортёр).
Он ничего не знает про анатомию: заглушка проходит все проверки и всё равно
остаётся заглушкой. Анатомию по-прежнему подтверждает только человек.

## Карта зубов (`DentalScene3D`) — модели НЕ используются

Не путайте два модуля. Анатомический viewer грузит GLB, а карта 32 зубов
(`src/components/patient/dental/DentalScene3D.tsx`) строит коронки в рантайме,
деформируя сферу, и никакого файла не читает.

Попытка заменить их восемью вылепленными коронками (`scripts/blender/build-chart-teeth.py`)
была доведена до рабочего состояния, сравнена вживую и **отклонена**: процедурные
коронки выглядят лучше. Причины и советы тому, кто будет пробовать снова, — в
шапке самого скрипта. Ассет `teeth-chart.glb` намеренно не хранится в репозитории,
чтобы не возить лишние 200 КБ в каждой сборке; при необходимости он собирается
одной командой.

## Ловушки сборки

Две ловушки, заложенные в скрипт `build-tooth-demo.py`, — их легко потерять при правках:

- соседние слои разведены зазором 15 мкм; при совпадающих поверхностях эмаль и
  дентин дают z-fighting, как только viewer включает прозрачность слоя;
- пульпа и корневой канал стыкуются плоскостью на уровне устья, а не входят друг
  в друга: перекрывающиеся тела дважды покрывают объём и читаются как дыра при
  поперечном разрезе.

## Обязательный контракт ассета

- Формат: glTF 2.0 Binary (`.glb`), одна основная сцена, все buffers и текстуры встроены в файл.
- Модель должна быть анатомически проверена стоматологом или медицинским 3D-специалистом. Лицензия и источник ассета должны быть сохранены рядом с документацией проекта.
- В основной сцене должны находиться шесть уникальных непустых Mesh или Group с точными ASCII-именами:
  - `Enamel`
  - `Dentin`
  - `Pulp`
  - `RootCanal`
  - `Cementum`
  - `PeriodontalLigament`
- Названия являются единственным способом определения анатомической части. Цвет, материал и положение не используются как идентификаторы.
- Вложенная геометрия каждого Group должна принадлежать только своей части. Не следует вкладывать один из шести именованных узлов внутрь другого.
- Ось, масштаб и единицы должны быть единообразными; рекомендуется метрическая шкала glTF (метры), применённые transforms и продольная ось зуба вдоль `+Y`.
- Нужны корректные normals, UV и PBR-материалы. Камеры, источники света, декоративный фон и постобработка в GLB не нужны — их создаёт viewer.
- Внешние URL и несжатые внешние `.bin`/изображения запрещены. Это сохраняет атомарную загрузку, отмену через AbortSignal и предсказуемое кеширование.

## Бюджет производительности

Целевые значения для одного зуба:

- до 200 000 видимых треугольников на desktop и желательно до 100 000 на mobile;
- не более 25 draw calls;
- текстуры не больше 2048×2048 без доказанной необходимости;
- суммарная GPU-память текстур около 64 МБ или меньше;
- Meshopt **или** Draco для mesh compression; KTX2/Basis для тяжёлых текстур. Не применять Meshopt и Draco к одному primitive одновременно.

Снижение полигонов не должно удалять клинически значимые границы пульпы, каналов, эмали и периодонта. После оптимизации ассет нужно снова показать медицинскому специалисту.

## Проверка и оптимизация через glTF Transform

После установки `@gltf-transform/cli`:

```bash
npx gltf-transform inspect public/models/tooth.glb
npx gltf-transform optimize public/models/tooth.glb public/models/tooth.optimized.glb --compress meshopt --texture-compress webp --flatten false --join false --instance false --simplify false
```

Рекомендуемые package scripts используют те же команды:

```json
{
  "inspect:model": "gltf-transform inspect public/models/tooth.glb",
  "optimize:model": "gltf-transform optimize public/models/tooth.glb public/models/tooth.optimized.glb --compress meshopt --texture-compress webp --flatten false --join false --instance false --simplify false"
}
```

Флаги `--flatten false`, `--join false` и `--instance false` сохраняют шесть
именованных анатомических узлов. `--simplify false` запрещает автоматическое
удаление геометрии, которое нельзя принимать без повторной клинической проверки.

KTX2 можно подготовить отдельной командой `gltf-transform uastc` или `gltf-transform etc1s`, если в окружении установлен `toktx` из KTX-Software. Не добавляйте скрытую системную зависимость от `toktx` в основной optimize script.

После оптимизации обязательно повторить `inspect`, проверить сохранность всех шести имён и сравнить файл визуально с исходником. Viewer по умолчанию продолжает загружать `/models/tooth.glb`; переключение на оптимизированный файл выполняется только после медицинской и визуальной проверки.
